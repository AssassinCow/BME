## 4. P0：会直接影响模型结论的问题

### 4.1 已修复：DTP cross-fit 覆盖完整外层训练集

修复前，`train_dtp_fold()` 通过 `assign_train_validation_test()` 固定保留一个内部 partition，用剩余两个
partition 训练和早停，然后直接拿该 checkpoint 推理外层测试。没有在选定 epoch 后用全部
外层训练受试者重拟合，也没有三模型 ensemble。

当前 anchors 的实测分配：fold 0-2 各为 21 个训练、10 个内部验证、8 个外部测试受试者；
fold 3 为 21/11/7；fold 4 为 20/11/8。即每个外层模型放弃约 10-11 名本可用于训练的受试者。
在总共只有 39 名受试者的任务中，这是高风险欠拟合和负优化来源。

现已实施三折 cross-fit DTP。每个内部模型在两个 partition 训练、对第三个产生 OOF；
三份 OOF 合并后只选择一次融合参数，外层测试用三个模型概率平均。它同时改善训练数据利用、
OOF 覆盖和 OOF→test 分布迁移，代价约为 3 倍 DTP 训练时间。

较省算力的次选：用一个内部 split 选择 epoch，再在全部外层训练受试者上按固定步数重训；但
重训后的概率校准可能不同，旧 alpha/beta 不一定稳定迁移，因此证据弱于 cross-fit ensemble。

### 4.2 已修复：50% 正例采样使用 neutral focal alpha

修复前，配置把每个 batch 的正例比例固定为 `0.5`。训练器又按未采样数据的原始正例率计算
`positive_alpha = clip(1-positive_rate, 0.5, 0.95)`。五折实测原始正例率约
`0.0556-0.0617`，得到 `positive_alpha=0.9383-0.9444`。

在已经 1:1 的正负 batch 内，单个正例相对负例的 alpha 权重约为 `15.2-17.0` 倍，再叠加
focal 和 Dice。这可能把状态概率整体推高、损坏校准，并迫使 beta/阈值承担补救工作。当前没有
DTP 实验输出能证明这种双重补偿有效。

现已保留 50% 正例采样并把 focal alpha 显式固定为 `0.5`；训练器会拒绝 50% sampling 与
非 0.5 alpha 的组合，metadata 同时记录实际 alpha 与未采样正例率。

### 4.3 已修复：融合门禁使用最佳 beta-only 增量对照

融合为

\[
z_{\mathrm{fused}} = z_{\mathrm{base}} + \beta
 + \alpha\left(z_{\mathrm{DTP}}-z_{\mathrm{base}}\right).
\]

修复前固定搜索 `alpha={0,0.25,0.5}` 与 `beta={-0.25,0,0.25}`，但内部门禁只要求
`alpha>0` 且优于 `(alpha=0,beta=0)`。若最佳 beta-only 候选已经取得全部收益，某个
`alpha>0` 组合只要没有完全破坏收益，仍可能通过；此时无法把提升归因于 DTP 信息。

现实现会分别选择最佳 `alpha=0` beta-only 与最佳 `alpha>0` 候选，要求后者 F1 至少再提高
`0.005`，异侧召回不降低且 FP/h 不增加；五折比较器要求五个内部增量门禁全部通过。

## 5. P1：统计偏差和稳定性风险

### 5.1 已修复：epoch 与融合参数分离选择

修复前，同一批 10-11 名内部验证受试者同时用于：选择训练 epoch、从 9 个 alpha/beta 中选组合、判定
internal gate。最多 40 次验证轮次乘 9 个组合，事件数量又有限，存在明显多重选择偏差。

现已按预先固定的 DTP-only window AUPRC 选择每个 partition 的 epoch，合并三份最佳 OOF 后
只执行一次融合网格和 internal gate。

### 5.2 已修复：外层五折不再条件早停

修复前只有 fold 0 外层 F1 等门禁通过才继续 fold 1-4，后续折零召回也会阻断。这一点已在文档
披露，但最终五折不再是预先无条件执行的外层评估。

现实现只用前折产物、run name、manifest/hash 和三份 cross-fit 签名保证串行完整性；内部或
外部门禁失败、单折零召回均不阻断后续折。五折完成后才由比较器作唯一晋级判断。

### 5.3 baseline OOF 与最终模型概率可能漂移

alpha/beta 在三折 baseline OOF 概率上选择，外层测试却使用全外层训练集拟合的 baseline
概率。两者的 logit 均值、方差与校准误差可能不同；固定 beta 尤其容易受此影响。

建议在每折产物中增加 OOF/test 概率分位数、logit 均值/标准差、Brier score 与 ECE 诊断；
cross-fit DTP ensemble 也应做同样检查。

### 5.4 DTP 因果模型仍保留两个恒定 future-missing token

当 `future_context_seconds=0` 时，模型仍把两个学习到的 future-missing token 送入 Transformer。
它们不会泄漏未来信息，但相当于额外的全局可学习 token，增加参数自由度且与“纯历史 token”
解释不完全一致。该问题优先级低于前三项，建议先做一个移除这两个 token 的小型消融，不直接
改正式模型。

### 5.5 PPG block 的有效性阈值较硬

PPG block 只有有效样本比例大于 0.5 才进入 dyadic pool 的有效集合；49% 与 51% 会被完全不同
处理。虽然原始 mask 和 SQI 特征仍存在，但该硬阈值可能在缺失边界产生不连续。建议记录各 block
有效率分布，再决定是否改为连续权重；目前没有证据支持立即修改。

## 6. 已确认实现正确或防护较强的部分

- 外层测试受试者与内部验证受试者显式隔离；
- baseline OOF 与 DTP 验证预测要求 `subject/session/timestamp` 一一对齐；
- `(alpha=0,beta=0)` 必须逐点、逐事件、逐指标精确复现 baseline；
- 因果候选强制 `future_context_seconds=0`；
- 数据、折分、baseline 产物和 resume checkpoint 均有哈希或签名门禁；
- 数据预处理对重复表头、冲突段、原子写入、多进程异常和断点恢复已有系统防护；
- XGBoost 使用三折受试者 OOF 选参，最终模型会在完整 outer-train 上重拟合；
- 事件 IoU 使用严格 `>0.25`，与当前已确认题面一致；官方匹配细节仍保持 UNKNOWN。

## 7. 本次已经修复的非统计问题

### 7.1 最终比较器证据链

`run_manifest.json` 升级为 schema 2，记录实验名、fold 和 PyTorch 版本。最终比较器现在会拒绝：

- 缺 manifest 或旧 schema；
- dirty 工作树产物；
- 同一实验混用 commit 或 resolved config；
- manifest 的实验名/fold 与目录不一致；
- 模型、预测、指标、融合选择或输入文件在 manifest 后被修改；
- 同一受试者出现在多个测试折；
- baseline 与 candidate 的逐折受试者集合或数据/折分指纹不同。

### 7.2 Windows DataLoader 内存压力

训练 loader 继续使用 8 个 persistent workers；验证/测试改为单独的
`inference_num_workers=2` 且不持久化，避免训练、验证、测试各 8 个进程同时驻留。该调整只影响
资源使用，不改变样本、预测或损失定义；实际 4080 吞吐需在 smoke/首折中观察。

### 7.3 正式执行入口

README 和 clean-room 手册已改为逐步骤命令。旧 `run_clean_retrain.ps1` 启动时会提示 deprecated，
不再作为正式入口。新手册在质量冻结、每折训练和候选路线前都有显式停点和验收条件。
