## 1. 文档目的与证据边界

本文把项目开始训练以来遇到的故障、已经实施的修复、当前低分根因和下一步验收标准集中记录，便于后续排查、跨电脑接力和最终报告复核。

状态标记：

- `OFFICIAL_CONFIRMED`：来自赛题或官方材料。
- `LOCAL_CONFIRMED`：已由当前代码、输出文件、五折实验或测试复核。
- `USER_PROVIDED`：来自实际运行日志。
- `UNKNOWN`：目前没有足够官方或本地证据，不允许凭空假设。

重要边界：当前事件匹配采用本地 Hungarian/greedy 实现。官方尚未完整说明一对一匹配、跨缺失区间事件和 partial coverage 的计分方式，因此本文 F1 是本地验证结果，不等于官方最终分数。

## 2. 当前结论摘要

用户按照 README 的顺序执行没有问题。当前低 F1 不是单一故障，而是三层问题叠加：

1. **后处理与评估口径问题是首要工程原因**：阈值搜索范围明显高于模型的实际概率尺度；训练标签包含 partial 事件，但评估只保留 full 事件。
2. **模型能力问题真实存在**：XGBoost 主要依赖佩戴手腕运动，对佩戴手与进食手不同的场景识别很弱；指数历史桶没有解决这一问题。
3. **数据质量问题需要单独处理**：一个疑似误写受试者被整体排除，16 个附件为未支持的二进制格式，部分受试者缺少 GYRO，且存在异常事件时长。

GPU、README 命令顺序、特征行对齐和外层受试者隔离不是当前低分的主要原因。

## 3. 历史问题及处理状态

### 3.1 全量审计在约 30% 处因 `UnicodeDecodeError` 中断

**原始现象（USER_PROVIDED）**

- `inspect_ppg_layout()` 使用 UTF-8 打开 ZIP 内 `.txt`。
- 第 332/1112 个附件附近出现 `0xff` 等二进制前缀，触发 `UnicodeDecodeError`。

**根因（LOCAL_CONFIRMED）**

- 部分扩展名为 `.txt` 的成员并不是 README 所描述的 UTF-8 制表符文本，而是另一种未识别二进制格式。
- 这不是普通编码切换问题，不能使用 `errors="ignore"`，否则会把二进制内容误当传感器文本。

**已经实施的修复**

- 新增 `UnsupportedSensorFormatError`，先检查 UTF-8 和必需表头，再读取数据。
- 审计遇到此类附件时记录 `status=unsupported_binary`，而不是中止整个任务。
- 保存二进制前缀的十六进制摘要用于定位，但不把内容误解析为传感器数据。

**代码与测试**

- `src/bme_eating/data/packet_reader.py`
- `tests/test_packet_reader.py::test_binary_sensor_member_is_reported_without_crashing_audit`

**状态：已解决崩溃；数据格式本身仍待官方确认。**

### 3.2 全量审计中断后不能从断点继续

**原始现象（USER_PROVIDED）**

- 全量审计单次运行时间长，一旦在中途失败便需要从头扫描。

**已经实施的修复**

- 审计结果按 ZIP 指纹写入 `schema_audit.checkpoint.json`。
- 重启后只处理未完成附件。
- 检查点签名包含参数和所选附件指纹；数据或配置变化时不会错误复用。
- `--no-resume` 可以明确要求从头重新审计。
- 成功生成最终 `schema_audit.json` 后删除临时检查点。

**状态：已解决并有代码路径保护。**

### 3.3 多进程预处理出现 `BrokenProcessPool`

**原始现象（USER_PROVIDED）**

- worker 抛出 `UnsupportedSensorFormatError` 后，主进程反序列化异常时提示 `__init__()` 缺少参数，进而导致整个进程池损坏。

**根因（LOCAL_CONFIRMED）**

- 自定义异常带三个构造参数，但没有提供可供 multiprocessing pickle 重建的协议。

**已经实施的修复**

- 为异常实现 `__reduce__()`，确保可跨进程序列化。
- `_preprocess_job()` 在 worker 边界把支持范围内的错误转换为结构化 issue，而不是让异常穿透进程池。
- 主进程对 worker 返回和意外异常均保留附件路径、哈希、异常类型与 traceback。
- 二进制附件写入 `outputs/indices/preprocess_issues.json`；其他预处理错误仍会令任务失败，避免静默丢数据。

**代码与测试**

- `src/bme_eating/data/packet_reader.py`
- `src/bme_eating/cli.py`
- `tests/test_packet_reader.py::test_unsupported_sensor_format_error_is_process_pool_pickleable`
- `tests/test_resilience.py::test_preprocess_job_reports_binary_attachment`

**状态：已解决。**

### 3.4 预处理长期停在 `1111/1112`

**原始现象（USER_PROVIDED）**

- 进度显示已完成 1111 个 future，但最后一个任务长期不返回。

**相关原因与修复（LOCAL_CONFIRMED）**

- 未支持二进制输入现在会提前识别并结构化返回，不再在深层解析中破坏 worker。
- 使用 `as_completed()` 收集任务结果并为每个附件关联上下文。
- segment 输出改为临时文件写完后原子替换，避免中断留下半个 `.npz`。
- `--overwrite` 会先删除该附件对应的旧 segment 和临时文件，避免新旧分段混合。
- 时间戳先排序并去重，深度数据集会拒绝时间戳非严格递增或损坏的 segment。

**验证**

- 后续全量预处理已生成 `segments.parquet`、`anchors.parquet`、`events.parquet` 和 16 条结构化二进制 issue。
- 当前没有再次出现 1111/1112 无返回的证据。

**状态：已解决运行阻塞；仍应保留超长附件耗时监控。**

### 3.5 其他脚本可能发生类似的缓存损坏或 worker 异常

**已经实施的系统性修复**

- 特征抽取 worker 统一返回结构化错误，写入 `feature_issues.json`。
- 特征结果和缓存均采用临时文件后原子替换。
- 特征缓存签名包含 segment 文件状态、锚点和特征配置，防止错误复用。
- 损坏 NPZ、缺字段、时间戳不合法会给出包含具体 segment 路径的错误。
- 后处理拒绝非有限概率、非法阈值和重复时间戳；重复时间戳会先聚合。
- 指标函数补充空集合和非法区间检查。

**状态：已解决主要同类故障，并加入回归测试。**

### 3.6 `Subjects missing from fold map`

**原始现象（USER_PROVIDED）**

- XGBoost 训练时有 4 名受试者存在于特征表，却不在 `subject_folds.json` 中。

**根因（LOCAL_CONFIRMED）**

- 原先 folds 只由具有有效 full 事件的受试者生成；有传感器 segment、但没有 full 事件的受试者被遗漏。

**已经实施的修复**

- `create_subject_folds()` 接收全部 segment 受试者集合。
- 没有 full 事件的受试者也会进入 folds，其事件计数填 0。
- 外层划分仍按受试者隔离，并尽量平衡受试者数、总事件、same 和 different 事件。

**状态：已解决外层 fold 缺失和受试者泄漏风险。**

### 3.7 XGBoost 提示 CUDA 模型与 CPU 输入设备不匹配

**原始现象（USER_PROVIDED）**

- XGBoost 模型运行在 `cuda:0`，预测输入为 pandas/NumPy CPU 数据，因而回退到 DMatrix，产生速度和内存警告。

**已经实施的修复**

- 训练继续使用 `tree_method=hist, device=cuda`。
- 若安装 CuPy，预测按批次把输入转到 GPU，避免不必要的 CPU DMatrix 回退。
- 没有 CuPy 时明确警告并安全回退到 CPU 输入。
- GPU 环境依赖补充 `cupy-cuda12x`。

**边界**

- `build_features.py` 的统计、SciPy 频域计算和多进程调度主要是 CPU 工作。
- 729 组事件后处理是 pandas/NumPy 顺序逻辑，目前也是 CPU 工作。
- GPU 是否充分利用影响耗时，不会解释当前事件 F1 很低。

**状态：GPU 训练和预测路径已修复；CPU 特征/后处理按设计保留。**

### 3.8 `train_xgboost.py` 长时间没有输出

**根因（LOCAL_CONFIRMED）**

- XGBoost 参数搜索、困难负样本挖掘和 729 组后处理原先缺少阶段提示；进程在正常计算时看起来像卡死。

**已经实施的修复**

- 添加 `[1/5]` 至 `[5/5]` 阶段提示。
- XGBoost 30 个 trial 添加 AUPRC/best 进度条。
- 每个 trial 写入带签名的 JSONL 检查点，并同步写 `trials.csv`。
- 后处理搜索添加 729 组进度条、当前 F1 和可恢复 JSONL 检查点。
- 损坏的尾部 JSON 行会被忽略；签名不一致时不会复用旧结果。
- `--no-resume` 可以强制重新开始 XGBoost 搜索。

**状态：已解决可观测性和中断恢复问题。**

## 4. 当前仍存在的问题

### 4.1 39/40 人与 1112/1140 附件差异

**证据（LOCAL_CONFIRMED）**

- README 预期：40 名正式受试者、1140 个附件。
- 当前审计：39 名受试者、1112 个附件。
- 原始传感器和用餐元数据中同时存在 `HNU212020`。
- 该 ID 有 28 个已下载附件和 7 条用餐记录。
- 当前规范只接受 `^HNU\d{5}$`，因此该 ID 被整体排除。
- `1112 + 28 = 1140`，`39 + 1 = 40`，数量差异被这一个 ID 完整解释。

**判断**

- 它很可能是 `HNU21020` 的源数据拼写错误，但目前仍是 `UNKNOWN`，不能未经确认直接改名。

**建议处理**

1. 向官方或数据平台确认 `HNU212020` 是否应映射为 `HNU21020`。
2. 确认后使用显式 alias 表，不使用模糊字符串纠错。
3. 修改后必须 `--overwrite` 重跑审计、预处理、特征和全部实验。

**状态：待官方确认，优先级 P0。**

### 4.2 16 个未支持的二进制附件

**证据（LOCAL_CONFIRMED）**

- 1112 个已纳入审计附件中，1096 个为当前支持的文本格式，16 个为二进制格式。
- 16 个附件涉及 11 名受试者。

**判断**

### 4.3 coverage 定义过严

**证据（LOCAL_CONFIRMED）**

- 267 条事件中，261 条为正时长。
- coverage 分布：`full=118`、`partial=125`、`none=18`、`invalid_duration=6`。
- 当前 full 判断要求覆盖时长与事件时长在约 1 ms 内相等。
- partial 事件覆盖率中位数约 `96.6%`；51 条超过 `99%`，44 条超过 `99.99%`。

**问题**

- 许多几乎完整的事件被排除出验证与测试。
- 1 ms 容差与 3 秒标签步长、重采样误差和 segment 边界并不匹配。

**状态：未修复，优先级 P0。**

### 4.4 训练标签与评估 truth 口径不一致

**证据（LOCAL_CONFIRMED）**

- `build_anchor_index()` 使用全部 `valid_duration` 事件生成状态和边界标签，包括 partial 事件。
- XGBoost 调参和最终评估只使用 `coverage == "full"` 的事件作为 truth。
- Baseline 的 95 个预测事件中，有 43 个与 partial 事件区间相交；它们当前可能被计为假阳性。
- 在不重训的诊断中，仅把 partial/none 区域作为 ignore zone，五折宏 F1 从 `0.1732` 上升到约 `0.2116`。

**建议方向**

- 先从官方确认 partial 区域计分规则。
- 本地验证至少应让训练、阈值搜索和评估使用一致的 censoring/ignore-zone 规则。
- 不能把 ignore-zone 诊断分数称为官方分数。

**状态：未修复，优先级 P0。**

### 4.5 后处理阈值搜索范围与模型概率尺度不匹配

**证据（LOCAL_CONFIRMED）**

- 当前搜索：`high_threshold=[0.5,0.6,0.7]`，`low_threshold=[0.2,0.3,0.4]`。
- Baseline 五折选中值全部落在下边界 `high=0.5, low=0.2`。
- 各测试折真实进食窗口的预测概率中位数仅约 `0.0835–0.1665`。
- 不重训模型，仅在内层验证集扩大阈值搜索，再冻结到外层测试折：
  - 五折宏 F1：`0.1732 -> 0.2537`
  - 汇总召回率：`0.1525 -> 0.3390`
  - 各折 F1：`0.1892, 0.3684, 0.3297, 0.2813, 0.1000`

**判断**

- 当前阈值范围是低事件召回的最强直接工程原因。
- 扩大范围后性能仍不够高，因此它不是唯一原因。

**状态：诊断已完成，配置尚未修改，优先级 P0。**

### 4.6 内层验证划分不稳定

**证据（LOCAL_CONFIRMED）**

- 外层五折按受试者划分，没有受试者泄漏。
- 内层验证使用 `sha256(outer_fold|subject_key) % 3`，没有按 full 事件数量或 same/different 分层。
- 五个外层折的内层验证集只有 7–13 名受试者、14–36 个 full 事件。
- fold 0 内层验证只有 14 个 full 事件，其中 same 10、different 4。

**风险**

- 小验证集上的阈值和超参数容易随少数事件波动。
- fold 4 在扩大阈值后仍只有 `F1=0.10`，说明验证选择不稳定。

**状态：未修复，优先级 P1。**

### 4.7 模型过度依赖手腕运动，异侧进食识别弱

**当前 Baseline（LOCAL_CONFIRMED）**

- 五折测试窗口 AUPRC：约 `0.245–0.355`。
- 五折宏事件 F1：`0.1732`。
- 合并事件统计：`TP=18, FP=77, FN=100`，precision=`0.1895`，recall=`0.1525`。
- same 命中：`16/51`。
- different 命中：`2/67`。
- 同侧窗口 AUPRC：约 `0.19–0.39`。
- 异侧窗口 AUPRC：约 `0.08–0.18`。

**特征重要性（五折 gain 归一化）**

- ACC：约 `48%–52%`。
- GYRO：约 `36%–38%`。
- PPG：约 `10%–14%`。

**Dyadic baseline**

- 五折宏事件 F1：`0.1670`，没有超过普通 baseline 的 `0.1732`。
- same/different 命中仍为 `16/51` 和 `2/67`。

**判断**

- 模型确实学到了部分进食信号，但高度依赖佩戴手运动。
- 单纯增加指数历史统计特征不能解决异侧识别和 PPG 利用不足。

**状态：模型能力问题，需在可信评估修复后再决定架构，优先级 P1。**

## 5. 已排除或不是主要原因的事项

### 5.1 不是 README 执行顺序错误

审计、预处理、特征、五折训练的执行顺序正确，当前产物也能对应到这些步骤。

### 5.2 不是特征漏行、重复或旧缓存混入

- `anchors.parquet`：1,629,918 行，无重复主键。
- `baseline.parquet`：1,629,918 行，无重复主键。
- `baseline_dyadic.parquet`：1,629,918 行，无重复主键。
- 三者的 `subject_key + segment_id + timestamp_ms` 完全一致。

### 5.3 没有发现分钟级全局时间戳错位

诊断平移实验中，4/5 folds 的最佳偏移为 0 秒；fold 0 的 60 秒偏移只带来约 0.0003 AUPRC 提升，不支持全局时间戳整体错位的假设。

### 5.4 不是模型完全没有学习

窗口 AUPRC 明显高于随机背景；理想窗口标签经过事件后处理时也能得到接近 1 的事件 F1。主链能够工作，只是当前概率校准、评估口径和异侧泛化不足。

### 5.5 GPU 利用率不是低分原因

XGBoost 的树训练可以使用 GPU；特征提取和后处理主要是 CPU。设备不匹配警告会降低预测速度或增加内存，但不会系统性地把事件召回压到当前水平。

## 7. 推荐修复顺序与验收标准

### 阶段 A：先建立可信数据与评估口径

1. 确认 `HNU212020` 的真实 ID。
2. 给 full coverage 使用与采样步长一致的容差或覆盖比例规则。
3. 将 partial/none 可观测边界定义为 ignore/censored 区域，统一标签、阈值搜索和评估。
4. 对 6 个非正时长、7 个极短、10 个超长事件形成逐条审计表，不自动删除。
5. 增加硬门禁：受试者数、附件数、未支持格式数、各传感器有效率和 coverage 分布不符合预期时停止训练。

**验收标准**

- 数据规模差异都有明确原因和处理决定。
- 同一事件不会在训练中作为正例、评估中又变成未知背景。
- 修订后的评估规则有单元测试和人工构造案例。

### 阶段 B：重新校准 baseline

1. 使用概率分位数或更低的绝对值扩展 high/low 阈值网格。
2. 内层验证按受试者、full 事件数和 same/different 尽量分层。
3. 保留外层五折不变；所有阈值只能在对应训练/验证折确定。
4. 重新输出五折总体、same/different、受试者级结果和每小时误报数。

**验收标准**

- 最优阈值不再系统性卡在网格边界。
- 五折均有稳定 recall，而不是由单个 fold 拉高平均值。
- same 与 different 分开报告，不能只给总体 F1。

### 阶段 C：再决定模型架构

只有阶段 A、B 完成后，才公平比较：

1. 当前 15 秒 XGBoost baseline。
2. 修订后的 dyadic XGBoost。
3. 多尺度 TCN。
4. ACC/GYRO 与 PPG 独立编码、PPG SQI 门控和晚期融合。
5. 轻量 Transformer/DTP-SQF；不以大型原始序列 Transformer 作为小样本首选。

需要优先解决的是异侧识别，而不是简单增加模型参数量。
